## Findings

| Sev | Location | Defect | Evidence | Required fix |
| --- | --- | --- | --- | --- |
| M | `public/render.js:33-41`, `server.mjs:29` | Remote resources still load while "external images" is off. Only `<img>` gets replaced, but the CSP allows `img-src https: http:`. | DOMPurify's `html` profile keeps `<input type="image" src=…>` and the legacy `background` attribute on `table`/`td`. Neither is in `FORBID_TAGS` or `FORBID_ATTR`, and the image loop only queries `img`. An imported untrusted `.md` file can therefore beacon to an outside host. | Remove `src`, `background` and `poster` from every element except `img` (add `background` to `FORBID_ATTR` and drop `input[type=image]`). Tighten the default CSP to `img-src 'self' data: blob:`, or document the residual risk. Add a hostile-Markdown browser check for these vectors. |
| M | `public/app.js` (`openFile` ~301, `syncSources` ~173-188, `acceptSuggestion` ~274-289) | CRLF files are silently rewritten and offsets drift. The textarea API value normalizes CRLF to LF, but `text` keeps the CRLF. | `editor.value !== text` right after load, so the first `input` event replaces `text` with the LF form of the whole document. Before that first edit, `activeEditor.selectionStart` uses LF offsets while `paragraphAt`/`applySuggestion` use CRLF offsets. `paragraphAt` can target the wrong paragraph, and `execCommand` inserts at the wrong range. The later `updateText(next)` repairs `text`, but the native undo stack keeps the bad insertion. Paragraphs sent to the model also carry stray `\r`. The "Markdown import exact" and "file writer exact content" checks would not catch this with LF fixtures. | Detect the EOL on open. Keep `text` in LF internally and restore the original EOL in `saveFile`, or refuse to edit CRLF files and say so. Add a CRLF round-trip test. `File.text()` also drops a UTF-8 BOM; preserve or report it (L). |
| M | `public/app.js:~363-368`, `~274` | Tab can apply a stale-but-valid suggestion to a paragraph away from the cursor. | Cursor moves (click, arrow keys, focus change) do not invalidate `currentSuggestion`, and `acceptSuggestion` ignores the selection. The revision and slice checks pass because the text did not change. A user who moves into another paragraph or a code block and presses Tab for indentation replaces a remote paragraph instead. `positionGhost` draws the hint at the cursor line, which makes the target look local. | Accept on Tab only when `selectionStart`/`selectionEnd` fall inside `[suggestion.start, suggestion.end]` (or the cursor's paragraph equals the suggestion range). Otherwise invalidate the suggestion and do the default Tab. |
| M | `ai.mjs:~69-70` | Fact gating trusts the category the model reports about itself. | `factualEditBlocked` only fires when `category === 'fact'`. A replacement that changes a fact but is labeled `grammar`/`wording` passes in both modes. With `factCheck=false`, a missing or invalid category defaults to `grammar` (`:69`). Even with `category: 'fact'`, a single `contradicted` item with one search-result URL authorizes the entire replacement, including other changed claims that are not in `factChecks`. The brief's rule "unsupported claims … cannot produce factual replacements" is therefore enforced only by the prompt. | State this explicitly as a limitation in the SRS and UI, or add a server check: in grammar mode, reject replacements whose token or number diff exceeds a threshold. In fact mode, require that every changed span is covered by a `contradicted` claim (claim substring present in the original). Add a test where `category:'grammar'` changes a number. |
| L | `server.mjs:49`, `public/app.js:~259-263` | A 429 from the single-flight guard turns automatic review off. | When the client aborts, the server releases `inFlight` only after the upstream fetch rejects. The next automatic request can get a 429. The client treats any automatic error as fatal: `auto-correct.checked = false`. | Do not disable auto review on 429 (or on aborts). Retry after the debounce. |
| L | `public/app.js:~284-288` | Accepting a suggestion schedules a re-review of the paragraph that was just accepted, through both the `input` path and an explicit `scheduleCorrection`. This can loop suggestions on the same text. | `execCommand` fires `input`, which calls `updateText(auto=true)`, and then line ~288 schedules again. | Suppress auto review for the accepted range until the next user edit. |
| L | `public/app.js` `saveFile` | `.txt` handle: the display name becomes `x.txt.md` (`safeFilename(handle.name)`) while the write still goes to `x.txt`. The save also overwrites without checking for external modifications. | `core.js` `safeFilename` appends `.md`. | Display `handle.name` verbatim. Optionally compare `getFile().lastModified` before writing. |
| L | `public/app.js:~363` | Tab with a non-applicable suggestion (unverified fact) moves focus out of the editor instead of indenting. | `return` without `preventDefault`. | Either indent, or dismiss the suggestion and indent. |
| L | `public/render.js:14-20` | The sanitized string is parsed again into a `<template>`. This is a mutation-XSS margin, not a demonstrated bug. | DOMPurify returns a string that is re-assigned to `innerHTML`. | Use `RETURN_DOM_FRAGMENT: true`. |

No XSS sink was found in the fact or suggestion UI: claims, explanations, titles, original text and replacement text all go through `textContent`. No credential exposure path was found in `server.mjs`/`ai.mjs`: upstream error bodies are not echoed, and the tests confirm `super-secret` is absent from `/api/config`. IME handling looks correct: `composing` gates scheduling, `compositionstart` invalidates, and Tab checks `isComposing`. This could not be cross-verified for Safari's event ordering, where `compositionend` fires before the final `input`, but in that ordering `updateText` would invalidate and reschedule, which is still safe.

## Verdict

**amend.** No finding is a hard blocker. The CRLF rewrite, the remote-resource bypass and the Tab target check should be fixed before claiming "file preservation" and "external images blocked". The fact-gating limitation should be fixed or documented explicitly before claiming that unsupported facts cannot produce replacements. Live provider behavior and the unsupplied browser scripts remain unverified.
