# Margin 네이티브 구현 재리뷰

결론은 **amend (경미)** 입니다. H1~H4는 소스에서 모두 해결된 것으로 확인되어 차단 사유는 없습니다. 리뷰는 읽기 전용 정적 검토였고, 빌드와 실행은 리뷰어가 하지 않았습니다. 리뷰 뒤에 반영한 조치는 아래 표의 "후속" 열에 적었습니다.

## 이전 지적 판정

| 항목 | 판정 | 후속 |
|---|---|---|
| H1 | 해결됨 | 시스템 autosave 뒤 `fileURL == nil` 단언 추가 |
| H2 | 해결됨 | 변형 빌드가 실행 취소 단계에서 `NSRangeException`으로 종료됨을 확인 |
| H3 | 해결됨 | - |
| H4 | 해결됨 | - |
| M1 | 부분 해결 | `MarginDocument` convenience `init()` 경로는 남아 있음 |
| M2, M3, M4, M5 | 해결됨 | - |
| M6 | 부분 해결 | 키 삭제 동작 없음, ad-hoc 서명 유지 |
| M7 | 해결됨 (요구 문구 축소) | - |
| L1, L2, L3 | 해결됨 | - |
| L4 | 미해결 | 번들 vendor 리소스의 버전·해시를 노출하지 않음 |

## 재리뷰에서 새로 나온 지적

| 지적 | 조치 |
|---|---|
| 복구본과 원본이 한 레코드를 공유해 이력이 섞일 수 있음 | 수정. `open(_:)`이 같은 `record.path`의 복구본을 찾아 그 창을 보여 줌. `recovered_copy_blocks_duplicate_open` 검사 추가 |
| `--quit-check`가 실패해도 종료 코드 0 | 수정. 실패 시 `exit(1)` |
| `--quit-check`가 어느 스크립트에도 없음 | 수정. `npm run test:native`에 추가 |
| `reopen_original_preserves_current`가 `flush` 없이도 통과 | 수정. 충돌 뒤 다시 고친 내용이 이력에 남는지 검사 |
| `reopenOriginal()`이 `fileModificationDate`를 갱신하지 않음 (추정) | 수정. 디스크의 수정 시각으로 갱신 |
| 재실행 시 레코드 하나만 복구되고 나머지 untitled 초안은 UI로 접근할 수 없음 | 미조치. 초안 목록 UI가 필요한 새 기능이므로 알려진 제약으로 기록 |
| `close()`에서 `flush` 실패 시 창 없는 문서가 남을 수 있음 (추정) | 미조치 |
| 손상 버전 검사가 깨진 JSON만 다룸 (해시 불일치, `record.json` 손상 미검사) | 미조치 |
| 시작 복구 경로가 `!uiCheck` 조건 때문에 헤드리스 검사에서 빠짐 | 미조치. 실제 실행에서 "로컬 자동저장본을 복구했어요." 표시만 확인 |
| `restoreOK`가 미저장 버퍼가 아니라 자동저장된 내용을 확인 | 미조치. 저장소 수준 검사(`native/Checks.swift`)만 미저장 내용을 다룸 |
